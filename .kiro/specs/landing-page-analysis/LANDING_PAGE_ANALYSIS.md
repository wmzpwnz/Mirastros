# Анализ стартовой страницы Mirastros

## Текущая структура

1. **Layout**: Preloader (первый визит) → LenisProvider → Navbar + main (viewport с Z-scroll).
2. **Шапка**: Design-system Navbar (sticky, z-50): логотип слева, слот для меню (пустой для гостей), справа — дети = «Войти» + «Регистрация» с `md:absolute md:right-8 md:top-1/2`.
3. **Hero**: чёрный фон, backweb.png/backmobile.png с параллаксом, радиальный оверлей, магический круг, 4 луча, логотип, длинный подзаголовок капсом, два CTA.
4. **Ниже**: Z-scroll (туннель), 21 секция, индикатор SCROLL + % внизу справа, боковое меню секций (z-40) справа по центру.

---

## Проблемы (почему «всё криво», «шапка несуразная»)

### 1. Шапка (Navbar)

| Проблема | Причина |
|----------|--------|
| **Шапка выглядит «как из другого сайта»** | Универсальный Navbar из design-system: логотип + пустое меню + кнопки. Для лендинга нет отдельной концепции — это шапка дашборда. |
| **Пустое пространство по центру** | При гостевом визите `menuItems = []`, блок «Desktop Menu» пустой. Получается: [Логотип] —— пусто —— [Войти] [Регистрация]. Визуально «дыра». |
| **Кнопки вставлены через children** | «Войти» и «Регистрация» рендерятся как дети после flex-ряда и позиционируются `absolute`. На части экранов могут наезжать на логотип или выглядеть оторванно от шапки. |
| **Мелкий логотип в шапке** | `h-10` (40px) на большом hero кажется мелким; нет отдельного размера для лендинга. |
| **Плотная высота** | `py-3` — шапка низкая; на широком экране может казаться «полоской». |
| **Нет явного «лендинг vs дашборд»** | Один и тот же компонент для главной и для /dashboard, из-за чего сложно сделать шапку главной более воздушной и цельной. |

### 2. Hero (первый экран)

| Проблема | Причина |
|----------|--------|
| **Перегруженность** | Много слоёв: фон, оверлей, магический круг, 4 луча, логотип, длинная строка капсом, 2 кнопки. Внимание размазано. |
| **Подзаголовок тяжёлый** | «ОТКРОЙ ДЛЯ СЕБЯ ЯЗЫК ЗВЁЗД И ПОЗВОЛЬ ВСЕЛЕННОЙ ВЕСТИ ТЕБЯ СКВОЗЬ ТАЙНЫ СУДЬБЫ» — одна длинная строка капсом, трудно быстро прочитать. |
| **Декорации выглядят шаблонно** | Круг + лучи — типичный «мистический» клипарт; без тонкой анимации и типа могут выглядеть дешёво. |
| **Дублирование логотипа** | Логотип и в шапке, и крупно в Hero — логично, но вместе с мелкой шапкой создаёт ощущение двух разных блоков. |

### 3. Общая композиция старта

| Проблема | Причина |
|----------|--------|
| **Много элементов поверх Hero** | Шапка + индикатор SCROLL + боковое меню секций. На первом экране уже три UI-блока. |
| **Неочевидный сценарий** | Не сразу ясно: «прокрутить вниз» или «нажать Регистрация». Туннель при скролле — нестандартно, но без подсказки может сбивать. |
| **Preloader только при первом визите** | 2 с фиксированным прогрессом может раздражать при повторных заходах, если что-то ещё догружается. |

### 4. Стили и код

| Проблема | Причина |
|----------|--------|
| **Мёртвый CSS** | В `global.css` остались `.navbar`, `.nav-left`, `.nav-right`, `.logo` с `position: absolute` и `mix-blend-mode: difference` под старую шапку. Текущая шапка их не использует — возможны путаница и лишний вес. |
| **Инлайн-стили в Hero** | Кнопки и блоки с дублированием цветов/градиентов вместо токенов design-system. |

## Варианты переосмысления

### Вариант A. Минималистичный лендинг (рекомендуемый старт)

**Идея:** Чистый первый экран, шапка — часть Hero, без лишнего.

- **Шапка**
  - На главной (`pathname === '/'`) — не использовать общий Navbar, а отдельный блок «LandingHeader»:
    - Прозрачный или полупрозрачный фон (не полоса `bg-black/80`).
    - Логотип по центру или слева, увеличенный (например 48px по высоте).
    - Справа только две ссылки: «Войти» и кнопка «Регистрация» в одной строке, без `absolute`, через flex.
  - На остальных страницах — текущий Design-system Navbar без изменений.

- **Hero**
  - Убрать магический круг и лучи (или оставить один тонкий акцент, например один луч или мягкое свечение).
  - Подзаголовок разбить на 2–3 строки, уменьшить капс (например только первые слова капсом или один короткий слоган).
  - Один главный CTA («Начать» / «Регистрация»), вторичный («Войти») — текстовая ссылка.
  - Фон и оверлей оставить, параллакс — по желанию, но без перегруза.

- **Первый экран**
  - Индикатор скролла: один элемент (стрелка вниз или «Листайте вниз»), без процента на первом экране.
  - Боковое меню секций: скрывать на Hero (показывать только после первого скролла) или делать полупрозрачным/маленьким.

**Плюсы:** Быстро внедрить, сразу уходит ощущение «криво» и «несуразная шапка».  
**Минусы:** Нужно добавить компонент LandingHeader и ветку по `pathname`.

---

### Вариант B. Шапка как часть Hero (единый блок)

**Идея:** Шапка визуально не отдельная полоса, а верх Hero.

- Полоса навигации без своего фона: логотип и кнопки с `text-white` и лёгкой обводкой/тенью для читаемости на фоне Hero.
- Высота шапки больше (например `py-4`/`py-5`), логотип крупнее.
- «Войти» и «Регистрация» всегда в одной строке с логотипом (flex, без absolute).

**Плюсы:** Цельный первый экран, шапка не «чужая».  
**Минусы:** На тёмном фоне нужна хорошая доступность (контраст, размер шрифта).

---

### Вариант C. Два режима шапки в одном компоненте

**Идея:** Тот же Design-system Navbar, но с пропом `variant="landing"`.

- `variant="landing"`: прозрачный/полупрозрачный фон, увеличенный логотип, больший padding, слот для CTA справа в одну линию (не children с absolute, а отдельный слот `rightActions`).
- В web-приложении на главной передавать `variant="landing"` и рендерить в правом слоте «Войти» + «Регистрация».

**Плюсы:** Один компонент, переключение по странице.  
**Минусы:** Усложнение API Navbar и стилей в design-system.

---

### Вариант D. Кардинальный редизайн первого экрана

**Идея:** Отдельная концепция главной: не «туннель с 21 секцией», а явный лендинг.

- Hero — один полноэкранный блок с чёткой иерархией: заголовок, короткий подзаголовок, один CTA.
- Ниже — блоки «Услуги» (таро, астрология, гороскоп и т.д.) в виде сетки или горизонтального скролла карточек, без Z-scroll на первом экране.
- Туннель и полный Z-scroll можно оставить как отдельную страницу «Все практики» или включать после блока «Услуги».

**Плюсы:** Понятная стартовая страница, меньше когнитивной нагрузки.  
**Минусы:** Больший объём работ и возможное изменение навигации по сайту.

---

## Рекомендуемый порядок действий

1. **Сразу (низкий риск)**  
   - Реализовать **вариант A** для главной: отдельный `LandingHeader` на `/`, логотип + «Войти» + «Регистрация» в одной строке через flex, без absolute.  
   - В Hero: упростить подзаголовок (2–3 строки, меньше капса), убрать или минимизировать круг/лучи, один явный CTA.  
   - Скрыть или ослабить индикатор процента и боковое меню на первом экране.

2. **Краткосрочно**  
   - Удалить или перенести неиспользуемые стили `.navbar`, `.nav-left`, `.nav-right`, `.logo` из `global.css`.  
   - Вынести стили кнопок Hero в токены/классы design-system.

3. **По желанию**  
   - Ввести `variant="landing"` в Navbar (вариант C) и постепенно перевести главную на него вместо отдельного LandingHeader.  
   - Или двигаться в сторону варианта D (отдельный лендинг и «Все практики»).

---

## Итог

Сайт не загружается не из-за падения, а из-за **ощущения «всё криво»**: шапка выглядит чужой и несуразной из-за пустого центра, absolute-кнопок и мелкого логотипа; Hero перегружен текстом и декорациями; на первом экране много элементов.  

Переосмысление по **варианту A** (отдельная шапка для главной + упрощённый Hero) даёт быстрый и предсказуемый результат; варианты B–D позволяют углубить редизайн по мере готовности.
