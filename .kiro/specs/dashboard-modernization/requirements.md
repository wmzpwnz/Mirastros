# Документ требований: Модернизация дашборда Mirastros

## Введение

Mirastros — мистическая/астрологическая платформа, дашборд которой является главной точкой входа после авторизации. Текущий дашборд представляет собой линейный Z-scroll туннель из 22 секций с монотонным дизайном, отсутствием персонализации и слабой навигацией. Цель модернизации — превратить дашборд в живое, персонализированное пространство, которое удивляет при первом входе, помогает пользователю ориентироваться в 21 сервисе и создаёт ощущение мистического путешествия.

---

## Глоссарий

- **Dashboard** — главная страница после авторизации (`/dashboard`)
- **HeroPanel** — первый экран дашборда с персональными данными пользователя
- **ServiceSection** — fullscreen-секция одного сервиса в Z-scroll туннеле
- **ZScrollTunnel** — эффект 3D-туннеля при скролле (GSAP + ScrollTrigger)
- **SectionNavigationMenu** — фиксированное меню навигации по секциям
- **User** — авторизованный пользователь платформы
- **CosmicOrb** — интерактивный 3D-элемент персонального астрального профиля
- **DailyPortal** — виджет ежедневных рекомендаций и задач
- **ServiceConstellation** — визуализация сервисов в виде созвездия
- **AstralTimeline** — лента последних консультаций пользователя
- **SubscriptionTier** — уровень подписки: `freemium`, `premium`, `platinum`
- **OnboardingFlow** — процесс первого знакомства нового пользователя с дашбордом
- **MicroAnimation** — небольшая анимация на интерактивном элементе (hover, click, focus)
- **WowMoment** — визуальный эффект при первом входе на дашборд
- **Background3D** — Three.js компонент с 3D-звёздами на фоне
- **DynamicBackground** — компонент динамического фона с blur-эффектом

## Требования

### Требование 1: Персонализированный Hero-экран с CosmicOrb

**User Story:** Как пользователь, я хочу видеть на первом экране живое, персонализированное пространство, отражающее мой астральный профиль, чтобы каждый вход на дашборд ощущался как уникальное событие.

#### Критерии приёмки

1. WHEN пользователь открывает дашборд, THE Dashboard SHALL отобразить HeroPanel в течение 3 секунд после загрузки данных пользователя.
2. THE HeroPanel SHALL отображать CosmicOrb — интерактивный 3D-элемент, визуально отражающий знак зодиака, текущую лунную фазу и уровень энергии дня.
3. WHEN пользователь наводит курсор на CosmicOrb, THE CosmicOrb SHALL реагировать плавной 3D-анимацией вращения с задержкой не более 16мс.
4. THE HeroPanel SHALL отображать имя пользователя, знак зодиака, текущую лунную фазу и дату в едином визуальном блоке.
5. WHEN данные лунной фазы загружены, THE HeroPanel SHALL обновить CosmicOrb без перезагрузки страницы.
6. WHERE пользователь имеет уровень подписки `premium` или `platinum`, THE HeroPanel SHALL отображать персонализированный астральный прогноз дня в виде краткого текста (не более 200 символов).
7. IF данные пользователя (birthDate, birthTime, birthLocation) отсутствуют, THEN THE HeroPanel SHALL отобразить призыв к заполнению профиля с кнопкой перехода в настройки.
8. THE HeroPanel SHALL поддерживать адаптивную вёрстку для экранов от 320px до 2560px без горизонтального скролла.

---

### Требование 2: DailyPortal — виджет ежедневных задач и рекомендаций

**User Story:** Как пользователь, я хочу видеть персонализированные рекомендации "что сделать сегодня", чтобы не теряться среди 21 сервиса и получать максимум пользы от платформы.

#### Критерии приёмки

1. THE Dashboard SHALL отображать DailyPortal как отдельный блок в HeroPanel с не менее чем 3 персонализированными рекомендациями.
2. WHEN пользователь открывает дашборд в новый день, THE DailyPortal SHALL обновить рекомендации на основе текущей лунной фазы, знака зодиака и истории использования.
3. THE DailyPortal SHALL отображать каждую рекомендацию с иконкой сервиса, кратким описанием (не более 80 символов) и кнопкой быстрого перехода.
4. WHEN пользователь нажимает на рекомендацию, THE Dashboard SHALL перейти к соответствующей ServiceSection или открыть сервис.
5. WHERE пользователь имеет уровень подписки `freemium`, THE DailyPortal SHALL отображать не более 2 рекомендаций с предложением апгрейда для получения полного списка.
6. IF история использования пользователя пуста, THEN THE DailyPortal SHALL отображать рекомендации на основе популярных сервисов для знака зодиака пользователя.
7. THE DailyPortal SHALL кешировать рекомендации в localStorage с ключом `daily_portal_{userId}_{date}` и инвалидировать кеш при смене дня.

### Требование 3: AstralTimeline — лента последних консультаций

**User Story:** Как пользователь, я хочу быстро получить доступ к своим последним консультациям прямо с дашборда, чтобы продолжить работу с результатами без поиска по истории.

#### Критерии приёмки

1. THE Dashboard SHALL отображать AstralTimeline с последними 5 консультациями пользователя из всех сервисов.
2. THE AstralTimeline SHALL отображать для каждой консультации: тип сервиса (иконка + название), дату, краткое превью вопроса или результата (не более 60 символов).
3. WHEN пользователь нажимает на элемент AstralTimeline, THE Dashboard SHALL перейти к детальному просмотру этой консультации.
4. THE AstralTimeline SHALL загружать данные параллельно из API Таро, Нумерологии и Снов с использованием `Promise.allSettled`.
5. IF консультации отсутствуют, THEN THE AstralTimeline SHALL отобразить призыв к первой консультации с анимированной иконкой.
6. THE AstralTimeline SHALL обновляться при возврате пользователя на дашборд после завершения консультации без полной перезагрузки страницы.
7. WHERE пользователь имеет уровень подписки `freemium`, THE AstralTimeline SHALL отображать консультации только из бесплатных сервисов.

### Требование 4: ServiceConstellation — визуализация сервисов

**User Story:** Как пользователь, я хочу видеть все сервисы платформы в виде интерактивной визуализации, а не линейного списка, чтобы навигация ощущалась как исследование звёздного неба.

#### Критерии приёмки

1. THE Dashboard SHALL отображать ServiceConstellation как альтернативный режим навигации по сервисам, доступный через переключатель в SectionNavigationMenu.
2. THE ServiceConstellation SHALL визуализировать все 21 сервис в виде интерактивных узлов, сгруппированных по категориям: Предсказания, Астрология, Эзотерика, Личностный рост.
3. WHEN пользователь наводит курсор на узел сервиса, THE ServiceConstellation SHALL отобразить всплывающую подсказку с названием, описанием и уровнем доступа.
4. WHEN пользователь нажимает на узел сервиса, THE Dashboard SHALL прокрутить к соответствующей ServiceSection.
5. THE ServiceConstellation SHALL визуально различать сервисы по уровню доступа: доступные (яркие), заблокированные (приглушённые с иконкой замка).
6. WHERE пользователь использовал сервис более 3 раз, THE ServiceConstellation SHALL выделить этот узел как "любимый" с визуальным отличием.
7. THE ServiceConstellation SHALL быть отключена на мобильных устройствах (ширина экрана менее 768px) и заменена стандартным списком.
8. THE ServiceConstellation SHALL поддерживать анимацию появления узлов при первом рендере с задержкой 50мс между узлами.

---

### Требование 5: Умная навигация SectionNavigationMenu

**User Story:** Как пользователь, я хочу иметь интуитивную навигацию по дашборду с визуальной иерархией и быстрым поиском, чтобы находить нужный сервис за 1-2 действия.

#### Критерии приёмки

1. THE SectionNavigationMenu SHALL группировать секции по категориям: Главная, Предсказания, Астрология, Эзотерика, Личностный рост, Магазин.
2. THE SectionNavigationMenu SHALL отображать иконку и название для каждой секции в списке.
3. WHEN пользователь вводит текст в поле поиска SectionNavigationMenu, THE SectionNavigationMenu SHALL фильтровать секции в реальном времени с задержкой не более 100мс.
4. THE SectionNavigationMenu SHALL отображать индикатор прогресса для текущей активной секции.
5. WHEN пользователь нажимает на секцию в меню, THE Dashboard SHALL прокрутить к ней плавно (smooth scroll) и закрыть меню.
6. THE SectionNavigationMenu SHALL поддерживать клавиатурную навигацию (Tab, Enter, Escape).
7. IF пользователь закрепил сервисы в избранном, THEN THE SectionNavigationMenu SHALL отображать раздел "Избранное" в начале списка.
8. THE SectionNavigationMenu SHALL сохранять состояние открытия/закрытия в sessionStorage.

### Требование 6: Система избранных сервисов

**User Story:** Как пользователь, я хочу закреплять любимые сервисы для быстрого доступа, чтобы не прокручивать весь туннель каждый раз.

#### Критерии приёмки

1. THE Dashboard SHALL предоставлять возможность добавить любой сервис в избранное через иконку-звезду в заголовке ServiceSection.
2. WHEN пользователь добавляет сервис в избранное, THE Dashboard SHALL сохранить это в localStorage с ключом `favorites_{userId}` и отобразить визуальное подтверждение (toast-уведомление).
3. THE Dashboard SHALL ограничивать количество избранных сервисов до 5 для `freemium` и до 10 для `premium`/`platinum`.
4. WHEN пользователь достигает лимита избранных, THE Dashboard SHALL отобразить уведомление с текущим лимитом и предложением апгрейда для `freemium`.
5. THE SectionNavigationMenu SHALL отображать избранные сервисы в отдельном разделе "Избранное" в начале списка навигации.
6. WHEN пользователь удаляет сервис из избранного, THE Dashboard SHALL обновить список без перезагрузки страницы.

### Требование 7: WowMoment — эффект первого входа

**User Story:** Как новый пользователь, я хочу испытать впечатляющий визуальный эффект при первом входе на дашборд, чтобы сразу понять уникальность платформы.

#### Критерии приёмки

1. WHEN пользователь входит на дашборд впервые (флаг `first_login` в localStorage отсутствует), THE Dashboard SHALL запустить WowMoment-анимацию длительностью не более 4 секунд.
2. THE WowMoment SHALL включать: появление звёздного неба, анимированное формирование созвездия знака зодиака пользователя, плавное появление HeroPanel.
3. WHEN WowMoment завершён, THE Dashboard SHALL установить флаг `first_login_shown_{userId}` в localStorage и не показывать анимацию повторно.
4. THE WowMoment SHALL предоставлять кнопку "Пропустить" для пользователей, не желающих ждать.
5. IF пользователь нажимает "Пропустить", THEN THE Dashboard SHALL немедленно завершить анимацию и показать дашборд в полном виде.
6. THE WowMoment SHALL быть отключён на мобильных устройствах (ширина экрана менее 768px) для оптимизации производительности.

### Требование 8: Онбординг для новых пользователей

**User Story:** Как новый пользователь, я хочу получить краткое руководство по дашборду, чтобы быстро понять, как пользоваться платформой.

#### Критерии приёмки

1. WHEN пользователь входит на дашборд впервые, THE Dashboard SHALL предложить интерактивный онбординг из 4 шагов после завершения WowMoment.
2. THE OnboardingFlow SHALL последовательно выделять: HeroPanel, DailyPortal, SectionNavigationMenu, первую ServiceSection с пояснительными тултипами.
3. WHEN пользователь нажимает "Далее" в онбординге, THE OnboardingFlow SHALL перейти к следующему шагу с анимацией.
4. THE OnboardingFlow SHALL предоставлять кнопку "Пропустить всё" на каждом шаге.
5. WHEN онбординг завершён или пропущен, THE Dashboard SHALL сохранить флаг `onboarding_completed_{userId}` в localStorage.
6. IF пользователь не заполнил birthDate, birthTime или birthLocation, THEN THE OnboardingFlow SHALL добавить шаг с предложением заполнить профиль для получения персонализированных данных.

---

### Требование 9: Виджет подписки и апгрейда

**User Story:** Как пользователь с freemium-подпиской, я хочу видеть контекстные предложения апгрейда в момент, когда я пытаюсь получить доступ к premium-функциям, чтобы понимать ценность подписки.

#### Критерии приёмки

1. WHERE пользователь имеет уровень подписки `freemium`, THE Dashboard SHALL отображать виджет апгрейда в HeroPanel с кратким описанием преимуществ premium.
2. WHEN пользователь пытается получить доступ к заблокированному сервису, THE Dashboard SHALL отобразить PaymentModal с описанием необходимого уровня подписки.
3. THE Dashboard SHALL отображать иконку замка на заблокированных ServiceSection в SectionNavigationMenu.
4. WHERE пользователь имеет уровень подписки `premium`, THE Dashboard SHALL отображать информацию о преимуществах `platinum` в виде ненавязчивого баннера не чаще одного раза в сессию.
5. THE Dashboard SHALL не отображать виджеты апгрейда пользователям с уровнем подписки `platinum`.

---

### Требование 10: Уведомления и лунные события

**User Story:** Как пользователь, я хочу получать уведомления о важных астрологических событиях (полнолуние, транзиты, ретроградные планеты), чтобы не пропускать значимые моменты.

#### Критерии приёмки

1. THE Dashboard SHALL отображать панель уведомлений с актуальными астрологическими событиями на ближайшие 7 дней.
2. THE Dashboard SHALL отображать уведомление о полнолунии за 3 дня до события с датой и описанием влияния.
3. THE Dashboard SHALL отображать уведомление о новолунии за 2 дня до события.
4. WHERE пользователь имеет уровень подписки `premium` или `platinum`, THE Dashboard SHALL отображать уведомления о планетарных транзитах, влияющих на знак зодиака пользователя.
5. WHEN пользователь нажимает на уведомление, THE Dashboard SHALL перейти к соответствующему сервису (Лунный календарь, Транзиты).
6. THE Dashboard SHALL хранить прочитанные уведомления в localStorage с ключом `read_notifications_{userId}` и визуально отличать прочитанные от непрочитанных.
7. IF уведомлений нет, THEN THE Dashboard SHALL скрыть панель уведомлений без пустого пространства.

### Требование 11: Дифференциация ServiceSection по категориям

**User Story:** Как пользователь, я хочу, чтобы секции разных категорий сервисов визуально отличались друг от друга, чтобы легче ориентироваться в туннеле.

#### Критерии приёмки

1. THE Dashboard SHALL разделить 21 ServiceSection на 4 визуальные категории с уникальными цветовыми акцентами: Предсказания (пурпурный), Астрология (синий), Эзотерика (изумрудный), Личностный рост (золотой).
2. THE ServiceSection SHALL отображать цветовой акцент категории в badge, рамке медиа-блока и кнопке действия.
3. THE ServiceSection SHALL поддерживать 3 варианта компоновки (layout): медиа слева, медиа справа, медиа на весь экран с текстом поверх — чередующихся для визуального разнообразия.
4. WHEN пользователь входит в зону видимости ServiceSection, THE ServiceSection SHALL запустить анимацию появления контента с задержкой не более 300мс.
5. THE ServiceSection SHALL отображать кнопку быстрого действия ("Начать гадание", "Открыть карту", "Рассчитать") с иконкой, соответствующей категории.
6. WHERE пользователь использовал сервис ранее, THE ServiceSection SHALL отображать дату последнего использования и краткий результат.

### Требование 12: Производительность и оптимизация

**User Story:** Как пользователь, я хочу, чтобы дашборд загружался быстро и работал плавно, чтобы не испытывать задержек при навигации.

#### Критерии приёмки

1. THE Dashboard SHALL достигать показателя Largest Contentful Paint (LCP) не более 3 секунд на соединении 4G.
2. THE Dashboard SHALL использовать React.memo для всех компонентов ServiceSection, предотвращая лишние ре-рендеры.
3. THE Dashboard SHALL использовать динамический импорт (next/dynamic) для компонентов Background3D, ServiceConstellation и всех ServiceSection.
4. THE Dashboard SHALL загружать видео в ServiceSection только при входе секции в viewport (Intersection Observer).
5. THE Dashboard SHALL мемоизировать вычисляемые значения (zodiacInfo, canAccessService) через useMemo.
6. THE Dashboard SHALL разбить PersonalHeroSection.tsx на компоненты не более 300 строк каждый.
7. IF компонент Background3D не поддерживается браузером (отсутствует WebGL), THEN THE Dashboard SHALL отобразить статичный CSS-фон без ошибок.

### Требование 13: Рефакторинг архитектуры

**User Story:** Как разработчик, я хочу, чтобы код дашборда был структурирован и поддерживаем, чтобы легко добавлять новые функции.

#### Критерии приёмки

1. THE Dashboard SHALL вынести константу ZODIAC_SIGNS в единый файл `constants/zodiac.ts` и использовать её во всех компонентах без дублирования.
2. THE Dashboard SHALL создать хук `useDashboardData` для централизованного управления загрузкой данных пользователя, лунной фазы и рекомендаций.
3. THE Dashboard SHALL создать хук `useFavorites` для управления избранными сервисами с поддержкой localStorage.
4. THE Dashboard SHALL создать хук `useNotifications` для управления астрологическими уведомлениями.
5. THE Dashboard SHALL устранить пропс-дриллинг, используя React Context для передачи данных пользователя и подписки в дочерние компоненты.
6. THE Dashboard SHALL создать директорию `components/dashboard/` для всех новых компонентов дашборда.
7. THE Dashboard SHALL покрыть все новые хуки unit-тестами с использованием React Testing Library.

---

### Требование 14: Доступность (Accessibility)

**User Story:** Как пользователь с ограниченными возможностями, я хочу пользоваться дашбордом с помощью клавиатуры и скринридера, чтобы иметь равный доступ к функциям платформы.

#### Критерии приёмки

1. THE Dashboard SHALL обеспечить навигацию по всем интерактивным элементам с помощью клавиши Tab в логическом порядке.
2. THE Dashboard SHALL предоставить aria-label для всех кнопок без текстового содержимого.
3. THE Dashboard SHALL обеспечить контрастность текста не менее 4.5:1 для основного контента согласно WCAG 2.1 AA.
4. WHEN пользователь активирует prefers-reduced-motion, THE Dashboard SHALL отключить все анимации, кроме необходимых для понимания интерфейса.
5. THE Dashboard SHALL предоставить alt-текст для всех изображений и aria-label для видео-элементов.
6. THE SectionNavigationMenu SHALL поддерживать закрытие по клавише Escape.
