# Полёт по направлениям — вариант для сравнения

Маршрут `/tunnel-preview` — отдельная рабочая версия движения по референсу владельца
https://sageeast.com/. Основная посадочная `/` пока использует прежнюю реализацию.

## Отличие от прежнего перехода

В одной перспективной сцене одновременно находятся несколько карточек направлений.
У каждой постоянная позиция слева или справа и собственная исходная глубина Z.
Прокрутка добавляет одинаковое перемещение ко всем плоскостям. CSS perspective
приближает ближние карточки, а дальние остаются видны за ними. Карточка проходит
мимо зрителя и выключается перед пересечением плоскости камеры. Между направлениями
нет смены полноэкранных панелей через opacity. Прозрачность используется только
для далёкой границы сцены, вступления и окончания.

Это самостоятельная реализация на имеющихся GSAP/ScrollTrigger, React и CSS 3D.
Код, фотографии и фирменные элементы Sage East не копируются. React Bits проверен
как исходная библиотека эффектов; Scroll Float/Scroll Reveal не реализуют требуемую
общую перспективную сцену, поэтому дополнительная библиотека не добавлена.

## Ресурсы и управление

- Используются 19 существующих направлений с существующими маршрутами.
- Изображения — WebP-кадры из собственных видео проекта, всего около 2 MB.
  Файлы видео не изменены; одновременно декодировать все ролики на телефоне не нужно.
- Исходный `/logo.png` сохранён.
- «Полёт / Список» переключает общую сцену и обычный доступный каталог.
- Стрелки переводят к направлению, карточка открывает его страницу.
- До загрузки JS остаются обычные ссылки; скрытые в полёте карточки не получают фокус.
- На touch используется один ScrollTrigger normalizer. Второй Lenis-контроллер
  на телефоне не включается. Высота адресной строки не перестраивает весь путь.
- При reduced motion нет инерционного доведения/запаздывания; просмотр списка
  остаётся доступным. Эта демонстрационная страница открывает выбранный полёт;
  автоматических бесконечных движений сцены нет.

## Проверка

Модель тестируется на одинаковое перемещение плоскостей, разные масштабы
перспективы, одновременную видимость непрозрачных карточек, отсутствие пустых
промежутков и настоящие маршруты/файлы ресурсов.

Браузерные проверки: Chromium и Linux WebKit, desktop и touch 390×844;
геометрия, свайпы, переключение списка, стрелки, окончание и переход в раздел.

Ограничение визуальной проверки: установленный Linux WPE WebKit показывает
плоские слои в снимках, хотя getBoundingClientRect вычисляет перспективу.
Это воспроизводится вне приложения на одном квадрате с translateZ(-1000px):
расчётный размер 100 px, снимок 200 px. Поэтому снимки WPE не подтверждают
отрисовку Safari на iPhone. Визуальную запись полёта делаем Chromium; после
публикации вариант нужно отдельно сравнить на настоящем iPhone.

Эта итерация проверяет тип движения. Финальная детализация оформления по
макетам и перенос на основную посадочную — отдельные следующие изменения.
