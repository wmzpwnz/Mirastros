# DeepSeek: серверное подключение

## Что работает без ключа

Короткое знакомство `/auth/onboarding` сохраняет имя, дату, город и время в общем
профиле. Значение имени берётся из справочника, число жизненного пути вычисляется
по правилам, положения небесных тел — Swiss Ephemeris. Итоговый портрет также
формируется без LLM. Эти шаги не ждут DeepSeek и не расходуют токены.

В backend уже есть единый `app/services/llm.py`, настройки `DEEPSEEK_API_KEY`,
`DEEPSEEK_API_URL`, `DEEPSEEK_MODEL`. Модель по умолчанию — `deepseek-chat`, адрес —
`https://api.deepseek.com/v1/chat/completions`. При пустом ключе, включая пробелы,
`generate` выдаёт `AIProviderUnavailable` до создания HTTP-клиента — как для
обычной выдачи, так и для потока. Ошибки провайдера не возвращают его сырой body.
Проверка доступности с неверным ключом не помечает модель загруженной.

## Когда потребуется ключ

Кнопка «Разъяснить» и серверные ограничения реализованы. Для реального ответа
провайдера потребуется ключ; для сохранения результатов, знакомства и тестов — нет. Автоматическая AI-генерация в короткое знакомство не
добавлена; существующий старый `/insight` не используется новым интерфейсом.
Наличие общего LLM-сервиса ещё не означает готовность тарификации всех старых
AI-модулей: перед их включением проверяем права, лимиты и историю отдельно.

## Как добавить позже

Ключ вводит владелец непосредственно на VPS в
`/srv/mirastros/shared/backend.env`. Это существующий закрытый файл окружения
backend; он не входит в архив релиза. В GitHub, чате и браузерной конфигурации
ключа быть не должно. Не использовать префикс `NEXT_PUBLIC_`.

При готовности функции:

1. Открыть файл через `sudoedit /srv/mirastros/shared/backend.env` на VPS.
2. Установить `DEEPSEEK_API_KEY` в реальное значение. Другие настройки и секреты
   оставить на месте; права файла не расширять.
3. Владелец перезапускает `mirastros-api` для чтения обновлённого окружения.
4. Выполняем один ограниченный запрос через утверждённый интерфейс с тестовым
   аккаунтом; проверяем пояснение, ограничение повторных запросов и учёт затрат.
   Значение ключа и содержимое файла в отчёт не копируем.

Вычисления остаются в алгоритмах модулей. В AI передаётся минимально необходимый
готовый результат, а не задача придумать положения планет или числовую матрицу.
Открытого бесконечного чата это подключение не создаёт.

## Проверки без секрета

`pytest -q test_llm_configuration.py test_welcome.py` проверяет отсутствие запросов
без ключа, модель/заголовки на имитации API, безопасную ошибку провайдера,
серверные расчёты и сохранение прогресса. Настоящий DeepSeek в этих тестах не вызывается.

## Ограниченные пояснения результата

Реализован серверный путь `/explanations/{kind}/{result_id}` (GET состояния/сохранённых
ответов, POST генерации). Он принимает только UUID результата и необязательный вопрос
до 300 символов. Контекст загружается из БД с проверкой владельца. Произвольный
`context_data` из браузера не принимается. Ответы не кэшируются общим HTTP-кэшем.

На странице Таро кнопка стоит после значений карт. ID сохранённого расклада теперь
возвращается клиенту. Само извлечение карт и выдача справочных значений больше не
вызывают LLM. Поддержано повторное открытие пояснения в истории сохранённых Таро,
нумерологии, И-Цзин, снов, Ленорман и синастрии. Руны и остальные несохраняемые
результаты пока не подключены: им сначала нужен серверный ID и проверка владельца.

Правила версии 1:

- Premium/Platinum с действующим сроком (или бессрочным доступом, как в текущей
  модели аккаунта). Пробная выдача отдельно контролируется сервером.
- Одно начальное пояснение и одно уточнение на результат. Повторное открытие и
  точное повторение уже выполненного запроса возвращают сохранённый ответ.
- `AI_EXPLANATION_DAILY_LIMIT=5`: предел обращений к провайдеру на пользователя
  за сутки UTC. Неудачные попытки также считаются, чтобы ограничить расходы.
- PostgreSQL блокирует строку пользователя при резервировании попытки. Запись
  pending сохраняется до обращения к провайдеру; параллельная генерация отклоняется.
  Ожидание провайдера — до 25 секунд, ответ — до 600 токенов. Зависшая резервация
  освобождается для повторной попытки через 60 секунд, но остаётся в дневном счётчике.
- Пробные кредиты расходуются только на успешно сохранённые ответы.
  `AI_EXPLANATION_TRIAL_CREDITS=0` по умолчанию: срок и количество пока не утверждены.
- Удаление исходного результата удаляет и его сохранённые пояснения. Технические
  события расхода содержат только тип, UUID и версию; текста вопросов/ответов в них нет.
- `AI_RESULT_EXPLANATIONS_ONLY=true`, `LEGACY_AI_CHAT_ENABLED=false`: ввод ключа не
  активирует прежние неограниченные AI-маршруты. Флаг purpose задаётся серверным
  кодом после проверок, а не приходит от клиента. Старый чат не может создавать или
  дополнять зарезервированные сеансы пояснений.

Используются существующие таблицы chat_conversations, chat_messages и analytics_events;
новой схемы или переноса пользовательских данных не требуется. Тесты проверяют
подписки, отсутствие ключа, изоляцию пользователей, повторное открытие, лимиты,
подмену контекста, удаление и ошибки провайдера. В CI параллельные запросы проверяются
на PostgreSQL в отдельной временной схеме с имитацией провайдера.

После публикации этой версии ключ понадобится для реального ответа, но его не нужно
передавать в чат. До добавления ключа кнопка честно сообщает о недоступности пояснений.
