# Персональное знакомство Mirastros

Веб-сценарий: `/auth/register` → `/auth/onboarding?start=1`; возвращение к портрету: `/auth/onboarding?view=portrait`, уточнение: `/auth/onboarding?edit=1`.

## Общие сервисы

Контракты нового сценария экспортируются из `packages/shared-core/src/types/welcome.ts`, а палитра утверждённого макета — из `packages/design-system/src/tokens/brand.ts`. Web использует эти общие определения.

Все новые API требуют авторизации и работают только с текущим пользователем:

- `GET /auth/onboarding/state`: профиль, прогресс, вычисляемый портрет.
- `POST /auth/onboarding/start`: идемпотентная отметка начала.
- `POST /auth/onboarding/step`: сохранение `name`, `birth` или `sky` и короткий результат. `null` у времени явно очищает прежнее значение.
- `POST /auth/onboarding/complete`: идемпотентная отметка завершения.
- `GET /auth/onboarding/places?q=...`: явный поиск Nominatim, не autocomplete; 1 upstream-запрос/секунду, кэш до 128 запросов на час, атрибуция OpenStreetMap в интерфейсе.

Используются существующие поля `users` и таблица `analytics_events`; миграция схемы не требуется. В событиях знакомства хранятся только версия и номер шага. Данные рождения остаются в общем профиле, имена и даты в геокодер не отправляются. Старый `/insight` сохранён для совместимости; новый сценарий его не вызывает.

## Расчёты и содержание

Справочник имён и русские символические тексты: `app/data/welcome.py`, с указанными словарными источниками. Неизвестные имена не получают выдуманной этимологии.

Число жизненного пути: существующая `calculate_life_path_number`, без отдельной формулы на клиенте. Астрологический обзор: Swiss Ephemeris из существующей зависимости Kerykeion, Moshier без сетевой загрузки эфемерид. Координаты → IANA через `tzfpy`; исторический UTC через `zoneinfo`. Асцендент вычисляется с равными домами, но дома не выводятся. Обзор не сохраняется как полная натальная карта и не заменяет расчётный контракт натального модуля. При неизвестном времени берутся границы местных суток и возможные знаки Солнца/Луны; асцендент отсутствует. Для неоднозначного/несуществующего времени при DST возвращается предложение уточнить данные.

Интерпретации символические, составляются из рассчитанных частей, без вызова LLM и расходования платных лимитов. Полный портрет воспроизводится по текущим данным профиля.

## Проверки

`pytest -q test_email_delivery.py test_welcome.py` в `apps/backend`; `npx vitest run --root apps/web`; `npx tsc -p apps/web/tsconfig.json --noEmit --incremental false`.

CI дополнительно проходит реальную регистрацию, JWT-вход, каждый шаг, сохранение профиля и завершение на чистом PostgreSQL через `deployment/smoke-backend.py`. Локальные браузерные проверки используют Chromium/WebKit, мобильный размер, изолированный backend и проверяют последовательность после посадочной, продолжение, неизвестное время и доступ к портрету. Производственные пользовательские записи для тестов не создаются.
