# Mirastros Foundation: общая структура платформы

## Фактическое состояние

Nx-монорепозиторий уже содержит `apps/web` (Next.js/React), `apps/mobile` (Expo/React Native), `apps/telegram-mini` и `apps/vk-mini` (Next.js), `apps/admin`, единый Python backend, `packages/shared-core` и `packages/design-system`.

Общая структура пока не означает полное переиспользование: Web имеет отдельный API-клиент, миниаппы — свои контексты авторизации; дизайн-система экспортирует DOM-компоненты и старую палитру, а утверждённый золотой стиль находится в Web CSS. В mobile указано другое имя пакета дизайн-системы (`@mirastros/design-system`), версии React/NativeWind отличаются от корня. Эти расхождения нужно устранять постепенно с проверкой каждой платформы.

## Целевая структура

- `apps/web`: публичная посадочная, туннель, кабинет и браузерные маршруты.
- Telegram/VK: тонкие оболочки для общего браузерного интерфейса, с адаптерами входа, safe areas, темы, back button и платежей платформы. Отдельные копии экранов модулей не развивать.
- `apps/mobile`: Expo-оболочка; нативные представления используют React Native, общие сценарии и модели из пакетов. HTML/CSS и GSAP нельзя автоматически считать нативными компонентами.
- `packages/shared-core`: типизированные API-контракты, сценарии модулей, валидация, состояние и права доступа. В общем коде отсутствуют прямые обращения к window/localStorage/Telegram.
- `packages/design-system`: единые токены, иконки, орнаменты и контракты компонентов; браузерные и нативные реализации через `.web.tsx`/`.native.tsx`. Утверждённый макет — единый визуальный эталон.
- Общие браузерные экраны следует выделять из работающего Web небольшими частями, затем подключать в миниаппы; не создавать ещё один независимый сайт.
- Backend: один аккаунт, профиль рождения, история, подписки, серверные расчёты и AI Core через DeepSeek. Платформенные идентификаторы привязываются к аккаунту; секреты AI остаются на сервере.

## Модули

У каждого направления общий идентификатор, цвет, ресурс, права доступа и контракт результата. Расчёт/сохранение/AI-разъяснение разделены. Интерфейсы могут различаться по направлению, но используют общий профиль и библиотеки. Оракул объясняет конкретный результат по доступному тарифу, не превращается в безлимитный общий чат.

## Очерёдность

1. Устранить блокировки загрузки Web, сохранить проверенный мобильный туннель, проверить desktop Safari и Chromium.
2. Завершить короткое персональное знакомство с сохранением в общем профиле; его API доступны всем клиентам.
3. Зафиксировать токены макета, перенести браузерные орнаменты/кнопки/поля в дизайн-систему без смены внешнего вида.
4. Согласовать имена пакетов и версии React, проверить сборки Web/Telegram/VK/Expo отдельно. Не выравнивать версии массовой заменой без совместимости Expo.
5. Переносить API-контракты и сценарии в shared-core; предоставить адаптеры хранения токенов: браузер, нативное защищённое хранилище, окружение миниаппа.
6. Один модуль довести целиком и подключить через общие сценарии ко всем оболочкам. Затем переносить остальные.

Изменения проходят через GitHub, проверки и PR. Рабочий сервер агенты напрямую не редактируют. Документ задаёт план; перечисленные переносы не объявляются уже выполненными.
