# Готовность релиза Mirastros

Дата проверки: 10 ноября 2026 года.

## Исправлено

- Stripe использует браузерный `@stripe/stripe-js`; отсутствие ключа обрабатывается.
  Отсутствие URL оплаты не считается успешной оплатой.
- Чат создаёт диалог и отправляет сообщения по существующим backend-маршрутам.
  Кнопка уточнения открывает интерфейс чата. Диалог сбрасывается при смене контекста.
- Google передаёт credential на сервер без доверия к декодированным браузером полям.
  Telegram передаёт оригинальный подписанный initData. Apple/VK не запускают
  незавершённые OAuth-потоки.
- Почтовые транспорты и параметры объявлены; синхронный SendGrid вынесен в поток.
  Нет повторной SMTP-отправки после ошибки SendGrid, тела писем и токены не логируются.
- Исправлены формат даты, JSX-расширение теста и проверка Headers в shared-core.
- Тестовые инструменты включены в manifest/lockfile.
- Production-клиент обращается к `/api` на своём домене.
- Подготовлены сборка релиза вне VPS, systemd, Nginx и ограниченный SSH-приёмник.
- Новый bootstrap создаёт схему только в пустой БД и никогда не удаляет таблицы.

## Проверено локально в облачном окружении

- Node.js 20.20.1; TypeScript без ошибок.
- Web: 200 тестов; shared-core: 79 тестов; почтовые транспорты: 3 теста.
- `nx build web` создаёт production standalone-сборку.
- Упакованный standalone-релиз запускается отдельным Node-процессом.
- Chromium: `/`, `/auth/login`, `/services/tarot` возвращают 200,
  исключений JavaScript не зарегистрировано.
- Backend импортируется со 178 маршрутами.
- Схема создаётся в изолированной PostgreSQL 14/pgvector.
- На этой БД работают readiness/liveness, регистрация (201), вход (200)
  и профиль с access token (200).

## Ограничения

Это не утверждение о работающем публичном сайте. Доставку проверенного релиза
через GitHub Actions, DNS/TLS и серверные smoke-проверки нужно завершить.
GitHub-интеграция не может управлять Actions secrets (403): их вводит владелец.
На момент проверки домен `vertigostra.ru` возвращал парковочную страницу Timeweb.

Реальные платежи, OAuth с аккаунтами провайдеров, отправка писем, пользовательские
данные и DeepSeek-ответы не входят в успешные локальные тесты. Наличие API-ключа
на VPS не означает, что он действителен. Для маленького VPS устанавливается
`requirements-server.txt`: локальные sentence-transformers/torch не используются.
Mobile и остальные клиенты этой проверкой не охвачены.

Первый bootstrap отражает текущие модели; существующие базы требуют отдельно
проверенных миграций. Скрипт не делает автоматические изменения существующей схемы.
