# Методика Матрицы судьбы

Дата проверки — 22 ноября 2026 года. Статус документа — проект для проверки методики.

Основание работы — расширенная редакция ТЗ владельца «Матрица судьбы Mirastros. ТЗ на толкования и данные», переданная 22 ноября 2026 года. При расхождении двух переданных редакций применяется расширенная редакция с разделом 0.

## Источники и степень подтверждения

S1 — https://ladinimatrix.ru/calculate-matrix-yourself/

Открытый пошаговый разбор с контрольной таблицей для 31.10.1984. Доступность проверена 22 ноября 2026 года. Сайт сообщает об использовании метода Ладини. Авторство этого сайта и его полномочия представлять автора метода не подтверждены.

S2 — https://ladinimatrix.ru/public-offer/

Оферта описывает материалы как основанные на информации из открытых источников. Это основание считать S1 вторичным изложением при текущем уровне проверки.

S3 — https://ladinimatrix.ru/ot-avtora-metoda/

Редакционная биография упоминает книгу «Матрица судьбы. Первоисточник», издательства БОМБОРА и Эксмо. Библиографическая карточка, издание, страницы с полными формулами и авторская принадлежность материалов ещё требуют проверки.

U1 — расширенное ТЗ владельца, раздел 2. Содержит формулы и два контрольных вектора. Второй вектор обозначен автором ТЗ как требующий независимой проверки.

Для полного подтверждения позиции нужны конкретное издание или авторский материал, страница либо раздел, воспроизводимый пример и отметка проверившего практика. Согласованность двух реализаций одного алгоритма подтверждает лишь совпадение реализаций.

## Числа и дата

Дата задаётся календарной датой в формате YYYY-MM-DD. В интерфейсе показывается день, месяц, год. Будущие и несуществующие даты отклоняются. Дата обрабатывается без преобразования через часовой пояс.

R(n) для положительного целого n сохраняет числа 1–22. Пока n больше 22, n заменяется суммой его десятичных цифр. Ноль, отрицательные и дробные значения являются ошибкой входа. Для года сначала складываются все цифры.

Контрольные примеры R(22) = 22, R(23) = 5, R(26) = 8, R(31) = 4, R(36) = 9. Год 1984 даёт 22, год 2000 даёт 2.

## Нумерация энергий и смысл позиций

Seed ТЗ предлагает VIII «Справедливость» и XI «Сила» с требованием сверить порядок по источнику. Существующий компонент DestinyMatrixView использует обратное соответствие. Окончательная нумерация ожидает подтверждённого источника.

Смыслы vertex_left, vertex_top, vertex_right, vertex_bottom в ТЗ явно оставлены для заполнения по источнику. Это обязательные входные данные генератора. Их трактовки ещё не подготовлены.

## Полная схема

Для внутренних точек, денег, отношений, кармического хвоста, талантов, родительских и детских позиций, возрастного круга и чакральной таблицы пока отсутствуют подтверждённые правила в материалах проекта. S1 перечисляет эти блоки без полного пошагового вывода.

Для каждого блока необходимо зафиксировать входные позиции, промежуточные операции, выходные позиции, расположение на карте, источник и независимый пример. Годовой прогноз и совместимость требуют отдельных правил.

## Состояние реализации

Тестовая страница matrix-preview.html использует matrix-atlas.js и формулы S1, включая позиции, ожидающие утверждения. Серверный сервис apps/backend/app/services/destiny_matrix.py сохраняет старый алгоритм v2. Например, для 15.05.1990 серверный центр равен 12, а центр по U1 равен 6.

Это существенное расхождение между демонстрацией и основным продуктом. При реализации matrix-core потребуются единый контракт, отдельный идентификатор методики, сохранение версии старых результатов и явный пересчёт. Ранее сохранённым данным нельзя молча присваивать новую методику.

## Порядок допуска контента

Согласно расширенному ТЗ, утверждение методики предшествует дальнейшим этапам. Следом создаётся matrix-core, затем проверяются полная схема и сохранение результатов, готовятся данные и генератор.

Базовые толкования хранятся как версионируемые записи по паре «энергия + позиция». Генерация создаёт draft. reviewed и approved требуют фактической проверки человеком по процедуре ТЗ. Смена статуса не может заменять проверку.

Ключ премиальной сводки должен учитывать версию методики и контента, язык, набор позиций и дату. Изменение текста или формулы требует нового ключа. Обычное открытие базовых толкований выполняется без вызова модели.

- Независимая проверка практиками нескольких дат.
