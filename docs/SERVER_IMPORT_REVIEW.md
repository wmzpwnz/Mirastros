## Проблемы, блокирующие готовность к слиянию

### 1. Stripe и TypeScript

`PaymentModal.tsx:13` импортирует `loadStripe` из `@stripe/js`. Такого пакета
нет в manifest и lockfile; браузерный SDK называется `@stripe/stripe-js`.
Он также отсутствует в lockfile, хотя это peer dependency React-интеграции.
Добавленный пакет `stripe` является серверным SDK и не заменяет браузерный.

`PaymentModal.tsx:197`: выражение для перенаправления имеет тип
`string | undefined`, а `window.location.href` требует строку.

`SocialLoginButtons.tsx:64`: `theme="dark"` не поддерживается установленным
Google OAuth SDK. Разрешены `outline`, `filled_blue`, `filled_black`.

В модуле оплаты Stripe загружается сразу, в том числе при отсутствии публичного
ключа. Нужны обработка отсутствующей конфигурации и проверка оплаты в sandbox.
Успешное создание подписки без URL платежа сейчас вызывает `onSuccess()`;
этот путь требует проверки подтверждённого статуса оплаты.

### 2. Чат не соответствует API

Новые методы API-клиента используют `POST /chat/complete` и `POST /chat/start`.
В текущем backend этих маршрутов нет. Реализованы
`POST /chat/conversations` и
`POST /chat/conversations/{conversation_id}/messages`.

Нужно согласовать создание диалога, его идентификатор и формат сообщений
с существующими схемами backend. `ChatInterface` пока нигде не импортируется
другими компонентами: перенос файла сам по себе не включает чат в интерфейс.
Компонент также не сбрасывает предыдущий диалог при смене контекста.

### 3. Социальная авторизация не завершена

Apple запускается через `fetch` на страницу авторизации; это не полноценный
переход браузера по OAuth-потоку. Страниц `/auth/apple/callback` и
`/auth/vk/callback` в текущем приложении нет. Нужны согласованный callback,
защита состояния OAuth и серверная проверка ответа провайдера.

Telegram передаёт строку `WebApp.initData` в метод `loginWithTelegram`,
который ожидает объект виджета с `id`, `auth_date`, `hash` и другими полями.
Нужно выбрать согласованный протокол и проверять подпись на backend;
простое преобразование строки в объект не заменяет проверку подписи.

Для Google требуется безопасное декодирование base64url вместо обычного
`atob` и обработка отсутствующей credential. Реальный вход не проверялся.

### 4. Почта может нарушить запуск backend

Новый обязательный импорт `aiosmtplib` отсутствует в requirements.
Опциональный `sendgrid` также не заявлен. В Settings отсутствуют поля
SMTP и SendGrid, которые читает новый сервис: конфигурация через `.env`
не обеспечивается самим `getattr`.

`SendGridAPIClient.send()` синхронный; `await sg.send(message)` некорректен.
Это также допускает попытку SMTP после уже состоявшейся отправки SendGrid.
Нужно выбрать и явно настроить почтовый транспорт, исключить повторную
отправку и не выводить письма с токенами в логи.

Для web-тестов использованы дополнительные инструменты из
`/workspace/.tools/web-test`, подключённые через локальные symlink в
`node_modules`: plugin-react, jsdom, Testing Library. Эти зависимости
по-прежнему не заявлены в manifest проекта. Это ограничивает воспроизводимость
тестов вне подготовленного облачного окружения.

Те же ошибки тестов были зафиксированы до импорта:

- shared-core ожидает обычный объект заголовков, клиент передаёт `Headers`;
- web принимает `01/01/1990`, хотя тест ожидает отклонение формата;
- `result-display.test.ts` содержит JSX и не загружается как обычный `.ts`.

Тесты не подтверждают новые OAuth, платежи, SMTP и чат: реальные внешние
запросы, платежи и отправка писем не выполнялись. Backend с БД не запускался.
Production-сборка импортированной версии не выполнялась: проверка типов
уже выявила блокирующие проблемы. Mobile и другие клиенты не валидировались.
